# MOSSES 레이아웃 (2026-11-26, 4차 디자인)

설정 메뉴에서 "모세스"(`layout: "mosses"`)를 고르면 오피스 바닥이 우주를 항해하는 항공모함의 HUD로 바뀜. 구성: 우주항법용 3차원 레이더 + 통신용 중간 터미널. 작업 공간 = 행성계, 탭 = 궤도, 에이전트 = 위성. 예전 "터미널" 레이아웃을 대체함(저장값 `"terminal"`은 `"mosses"`로 읽음).

목적: 게임 화면이 아니라 실제로 동작하는 시스템. 모든 글자와 숫자는 실제 값(상태, 경과 시간, 개수, 발생 시각). 우주 배경·행성·항모 도면·빛번짐 그림은 `tools/mosses-assets.py`가 노이즈와 도형으로 직접 만듦(외부 그림 없음).

## 화면 (한 화면)
| 영역 | 내용 | 동작 |
| --- | --- | --- |
| 머리줄 | 가동 시간(MET), 행성계·위성·작업 중·수신 대기 개수, 현지 시각, UTC | 표시만 |
| NAV RADAR 3D | 작업 공간 1개 = 기울어진 레이더 면 위의 행성계(행성, 탭마다 궤도 1개, `SYS-01`). 에이전트 1명 = 궤도 선 위의 위성(달 그림 + 상태색 테두리 + `SAT-01` + 이름). 위성은 궤도를 따라 돎. CLUSTER에서 위성에 마우스를 올리면 상태·경과·하는 일 카드가 뜸 | 위성을 한 번 누르면 채널(터미널 창)이 열리고 표적으로 고정됨 |
| COMM · INCOMING | 승인 대기 요청(요청 글, 경과 시간) | 승인·거절·채널 열기. 2건까지 펼쳐 표시 |
| COMM · CHANNELS | 전원 표(ID, 이름과 하는 일, 행성계/탭, 상태, 경과) | 행을 누르면 채널이 열림. 행에 마우스를 올리면 레이더의 그 위성에 카드가 뜸 |
| COMM · LOG | 승인 요청 수신, 작업 보고, 응답 결과, 채널 개방(시각 포함) | 최근 6건 |

시작할 때 기동 점검(통신 연결, 행성계 수, 위성 수, 수신 대기 수)을 약 2.4초 표시한 뒤 계기가 차례로 열림. 클릭하면 건너뜀. 별 층과 방위 눈금은 계속 흐름(항해 중).

## 두 단계 화면
| 단계 | 내용 | 들어가는 법 |
| --- | --- | --- |
| CLUSTER (01 OVERVIEW) | 모든 작업 공간을 행성계로 표시 | 시작 화면. 상단 띠의 CLUSTER, 화면의 `← CLUSTER` |
| SYSTEM (02 <작업 공간 이름>) | 들어간 작업 공간 하나만 크게 표시. 위성마다 이름·상태·경과·하는 일 카드. 배경에 가까운 행성이 보임. CHANNELS 표는 그 작업 공간의 위성만 | CLUSTER에서 행성이나 행성계 이름을 누름 |

단계를 바꿀 때 약 1.3초 로딩 화면(목적지, 궤도 수, 위성 수)이 나온 뒤 새 화면이 열림. 현재 단계는 `shared("hansol.mzView")`에 저장함(상단 띠와 바닥이 같이 읽음). 위성은 두 단계 모두 한 번 누르면 채널이 열림.

## 상단 띠와 하단 줄
- 상단 띠(`mzBand`): MOSSES 표시, CLUSTER / SYSTEM 위치, 상태별 개수(누르면 기존과 같은 목록·승인함), 연결 수, RADAR / BOARD 전환, 대화, 설정.
- 하단 줄(`mzFooter`): 위성·행성계 수, 최근 갱신.

## 구현 메모
- `mzStartTimer`(main.js `init`에서 시작)가 움직임이 있는 동안만 40 ms마다, 그 밖에는 1초마다(궤도) 다시 그림. 위성은 1.5초 뒤 위치를 향해 1.5초짜리 `transition`으로 움직임(다음 그리기가 늦어도 멈추지 않음).
- 렌더 중에 만든 타이머는 다시 그리기를 못 함(2026-11-26 실측). 반드시 `init`에서 시작함.
- 별 층·방위 눈금·깜빡임은 `.loop`, 회전 고리는 `.spin`(타이머 없음).

## 점검 명령 (클릭 없이 화면 보기)
`herdr-app do hansol.mosses:<what>`: `boot`(기동 화면 다시), `peek`, `peek:off`, `lock:<n>`(n번째 위성을 채널을 열지 않고 고정), `open:<n>`(n번째 위성을 누른 것과 같음), `enter:<n>`(n번째 행성계 진입, `enter:0`은 CLUSTER 복귀), `hover:<n>`(n번째 위성에 마우스를 올린 것과 같음).
`peek`은 콘솔을 오른쪽 절반에 그림(왼쪽 창에 가릴 때 화면 확인용).
창이 화면에 보이지 않으면 Herdr가 다시 그리지 않음. `herdr-app shot`을 두 번 연속 찍어 두 번째 그림을 봄.

## 표시 규칙
- 하는 일: 승인 대기면 요청 글, 아니면 터미널이 알려 준 활동 글 전체(`common.js` `activityText`). 도구 이름뿐이면 비움.
- 한 행성계에 위성이 5개 이상이면 CLUSTER에서는 ID만 표시하고 이름은 카드에서 보여 줌.
- 화면의 숫자는 모두 실제 값. 장식용 눈금·수치는 두지 않음.

## 남은 것
- `mosses-model.js`의 일부 함수(1·2차 디자인용)는 지금 화면에서 쓰지 않음.
- 위성이 많거나 화면이 좁으면 이름표가 서로 겹칠 수 있음.

## 5차 설계 (2026-11-27): 궤도 층 분리, 작업 중심 표시

- **궤도 층**: 위성은 독립 화면(`MzOrbit`, `cx.new`)이 초당 약 25회 따로 그림. 바닥 전체는 다시 그리지 않음. 위성 위치는 시각만으로 계산(각도 = 시작각 + 2π × 현재 시각 / 주기)하므로 항상 궤도 위에 있고, 화면 폭이 바뀌어도 제자리를 찾아 움직이지 않음. 바닥이 그릴 내용을 `SCENE`에 쓰고 궤도 층이 읽음.
- **이름표**: 윗줄 = 하는 일, 아랫줄 = 상태 · 탭 번호 · 에이전트 이름. 임의 번호(`SAT-01`)는 삭제하고 실제 값(작업 공간 / 탭 번호)만 표시.
- **화면 구성**: 상단 계기 줄, 채널 표, 로그 판 삭제. 제목(01 OVERVIEW / 02 작업 공간 이름), 장면, 수신함 하나로 구성.
- **수신함(INBOX)**: 승인 요청(승인·거절·열기)과 작업 보고(확인·열기). "확인"을 누른 보고는 목록에서 내려감(공유 값 `hansol.mzAck`, 에이전트 id → 보고 시각).
- **터미널 창**: 바탕 `#0b1628`(판과 같은 남색), 머리는 두 줄(하는 일 / 상태 · 에이전트 · 작업 공간 / 탭).
- 검토 명령 `hover:<n>`은 삭제(이름표가 항상 보임).

## 6차 설계 (2026-11-27): 궤도 층을 도형(경로)으로

- **측정한 원인**: 상자·그림·글자는 화면 점 단위로만 놓임. 느린 이동이 1점씩 끊겨 보였음. 직접 그리는 도형(`paint_path`)은 점 사이에도 놓임.
- **궤도 층**: 위성, 상태 고리, 꼬리, 이름표를 잇는 선을 모두 도형으로 그림. 도형 수는 위성 수와 무관하게 10개 안팎. 측정값 초당 약 34회(`herdr-app do hansol.mosses:stat` 두 번의 `hansol.mzStat.n` 차이).
- **이름표**: 행성계 옆에 고정(글자는 움직이지 않음). 이름표나 현황 줄에 마우스를 올리면 그 위성을 잇는 선이 밝아짐.
- **버튼**: 대각 두 모서리(왼쪽 위·오른쪽 아래)를 자른 모양(`button()`, 터미널 창의 승인·거절).
- **수신함**: 작업 보고 아래 "에이전트 현황" 목록을 "현황 켜기/끄기"로 전환(`hansol.mzList`).
- **배경**: 별 반짝임 2층, 행성 뒤 빛무리, 궤도의 먼 쪽 절반은 흐리게.

## 디자인·UX 검토 반영 (2026-11-27)

디자인 품질(Opus)과 UX(Sonnet) 독립 검토 2건을 받아 반영함.
- 그림: 행성 원본 560px, 줄무늬 약하게, 밤 쪽 어둡게, 남색·청록 계열로 통일. 빛무리 가장자리 선 제거. 별 수와 밝기 축소.
- 위성: 어두운 구슬 + 초승달 밝은 면, 상태색 고리(작업 중은 천천히 호흡), 선택·올림은 청록 점선 고리.
- 연결선: 이름표에서 28px 수평 뒤 위성으로 꺾임. 위성이 행성 뒤에 있을 때 행성 위를 지나는 부분은 그리지 않음.
- 이름표: 평소 상자 없음(상태색 세로 막대 + 두 줄). 선택·승인 대기일 때만 틀. 모델명은 풍선말로 이동.
- 수신함: 둘째 줄은 작업 공간 / 탭. "열기"가 읽음 처리를 겸함. 현황 목록은 위에 이미 나온 에이전트를 제외.
- 알림: 새 승인 요청과 응답 실패를 토스트로 알림.
- 터미널 창: 승인 대기 중에는 머리 윗줄에 요청 내용 표시. 아래 줄의 크기 숫자 삭제.
- 하단 줄: 상단과 중복인 상태 범례 삭제.

## 현황 판, 연계·서브에이전트·셸 표시 (2026-11-27)

- **AGENT STATUS 판**: 수신함 아래의 별도 판(팝업 아님). 작업 공간별로 모든 에이전트의 지금 하는 일과 지금까지 한 일(최근 3건, 시각 포함)을 표시. 누르면 그 에이전트 창이 열림. 수신함의 켜기/끄기 버튼은 삭제.
- **작업 기록**: 바닥이 에이전트별 작업 제목 변화를 기록(에이전트당 최근 8건, 공유 값 `hansol.mzHist`).
- **에이전트 간 연계**(`parent_id`): 두 위성 사이 점선 + 리더에서 받는 쪽으로 달리는 점. 이름표에 "↳ 연계", 현황 판에서는 리더 아래 들여쓰기와 리더 작업명 표시.
- **서브에이전트**(`helpers`): 위성 둘레를 도는 작은 점(최대 5개), 이름표에 "서브 n".
- **셸 실행 대기**: 위성 둘레를 도는 보라색 호 3개.
- 검토 명령 `hansol.mosses:fx`: 위 세 표시를 30초 동안 첫 위성들에 보여 줌(표시만).

## 수신함: 승인 요청 전용 + 선택지 (2026-11-27)

- 수신함은 승인 요청만 표시. 작업 보고는 아래 AGENT STATUS 판에서 확인.
- 요청마다 터미널 화면의 선택지를 읽어(`hc read` → `approvalPlan`) 선택지별 버튼으로 표시. 누르면 그 번호를 전송. 전송 직전에 화면을 다시 읽어 같은 번호·같은 문구가 있을 때만 전송(`answerOnce`에 `{ n, label }`).
- 선택지를 읽지 못하면 기존 승인/거절 버튼 표시.
- 검토 명령 `hansol.mosses:fx`: 요청이 없을 때 선택지 3개짜리 견본 요청도 30초간 표시(주소가 없어 눌러도 전송 안 됨).

## 상단 띠·터미널 창 버튼 대각 잘림 통일 (2026-11-27)

- 상단 띠: 화면 위치(CLUSTER/SYSTEM), 상태 칩, RADAR/BOARD, 대화·설정 버튼을 왼쪽 위·오른쪽 아래가 잘린 판으로 변경. 폭이 내용에 따라 달라지므로 양 끝 조각(그린 선) + 가운데 상자로 구성(`cutRow`).
- 터미널 창 머리의 버튼은 기존 모양 유지(사용자 지시로 변경 취소).

## 워프·시점 회전·위치 변경·등장 효과 (2026-11-27)

- **진입**: OVERVIEW의 `ENTER` 글자 삭제. 행성(또는 작업 공간 이름)을 누르면 워프로 진입(`MzWarp`, 1.1초, 바뀌는 시점 0.55초). 2차 개선: 누른 행성으로 다이브(행성이 커지며 가운데로), 빛줄기 3층(먼 줄기 가늘고 느리게, 가까운 줄기 굵고 머리가 밝음), 바뀌는 순간은 어두운 막이 화면을 완전히 가림(`warpVeil`), 그 뒤 빛 고리가 퍼지며 새 화면이 나타남. 흰 화면 번쩍임은 삭제. 돌아갈 때는 줄기가 가운데로 모이고 떠나는 행성이 멀어짐. 상단 띠의 CLUSTER나 점검 명령으로 바뀔 때는 후반부만 재생. 기존 로딩 화면(`mzLoad`)은 삭제.
- **시점 회전**: 빈 바닥을 끌면 레이더 면이 돎(좌우 = 회전, 위아래 = 기울기 0.12~0.9). 2차 개선: 궤도 선도 궤도 층(`MzOrbit`)이 그리므로 회전·기울기 중에 바닥 전체를 다시 그리지 않음(먼 쪽 반은 행성 뒤에서 가려짐). 행성 크기는 기울기와 무관하게 고정(`ringsAr`). 회전하면 제목 옆에 `시점 초기화` 버튼 표시.
- **행성 끌기**: 끌고 가는 행성은 궤도 층이 60프레임으로 그리고, 바닥은 놓일 칸이 바뀔 때만 다시 그림.
- **작업 공간 위치 변경**: OVERVIEW에서 행성을 끌어 다른 칸에 놓으면 순서가 바뀜. 순서는 공유 값 `hansol.mzOrder`(작업 공간 키 목록)에 저장하고 현황 판도 같은 순서를 따름. 새 작업 공간은 뒤에 붙음.
- **에이전트 등장·소멸**: 새 에이전트는 위성이 점에서 커지며 고리 2개가 퍼지고 불꽃이 모임, 이름표는 0.6초 동안 나타남. 사라진 에이전트는 마지막 자리에서 위성이 줄어들며 분홍 고리와 불꽃이 퍼지고, 이름표는 `연결 종료`로 0.6초 동안 흐려짐. 처음 화면을 켤 때 있던 에이전트에는 효과 없음.
- **행성 12종**: 용암(빛나는 균열), 얼음(청록 균열), 고리 있는 사막 가스, 녹색 가스 추가(`tools/mosses-assets.py` `new_planets`). 작업 공간마다 다른 행성을 배정(`planetsFor`: 해시 후 빈 번호, 12개까지 중복 없음).
- **부하**: 궤도 층은 평소 약 20프레임(이전 약 34), 등장·소멸·회전 중에만 60프레임. BOARD 화면에서는 궤도 층 정지.
- 점검 명령 추가: `view:<회전>:<기울기>`(끈 것과 같음), `order:<원래 번호>:<새 번호>`(행성을 끌어 놓은 것과 같음), `stat`에 바닥 그리기 횟수(`floor`) 추가.

## MOSSES BOARD 재구성 (2026-11-27)

MOSSES 레이아웃의 BOARD는 MOSSES 전용 화면(`mzBoardView`). 길드·오피스의 BOARD는 그대로.
- **칸 = 작업 공간(행성계)**: OVERVIEW와 같은 순서(`hansol.mzOrder`). 칸 머리에 행성 그림, 이름, 상태별 수. 머리를 누르면 RADAR로 바꾸고 그 행성계로 진입. 머리의 행성 그림을 오른쪽 클릭하면 행성 메뉴.
- **카드 = 에이전트**: 하는 일, 상태, 탭, 경과 시간, 서브·연계 표시, 최근 작업 2건. 정렬은 승인 대기, 작업 중, 작업 보고, 대기 중, 셸 순. 누르면 터미널 창.
- **오른쪽**: 승인 요청 수신함(선택지 버튼 포함). 현황 판은 카드가 대신하므로 BOARD에서는 표시 안 함.
- 데이터 계산(`mzSystems`, `mzTrack`)은 RADAR와 같은 함수라서 BOARD만 켜 둬도 작업 기록과 현황 판 값이 갱신됨. 별 흐름은 없음(부하 축소).
- MOSSES에서는 `레벨 업` 알림을 띄우지 않음(레벨 표시 안 함).

## 작업 중 강조 (2026-11-27)

작업 중은 밝은 청록(`WORK` #3ee6d2)과 움직임으로, 대기 중은 흐리게 표시해 구별함.
- 명패·카드: 작업 중 = 청록 배경과 테두리, 깜빡이는 굵은 상태 막대, `● 작업 중`. 대기 중 = 불투명도 0.72, 옅은 막대, 회색 글자.
- 위성: 작업 중 = 청록 고리와 둘레를 도는 밝은 호 2개. 대기 중 = 옅은 회색 고리.
- 위성 둘레 표시는 자리를 나눠 겹치지 않음(`LANE`, 위성 가장자리에서 px): 상태 고리 4(승인 대기 맥동 포함), 작업 중 호·셸 대기 호 10(한 에이전트에 동시에 나오지 않음), 선택 점선 14, 서브 에이전트·셸 표식 21.
- **서브 에이전트·셸 수량**: 위성 둘레에 서브 에이전트 1개당 청록 점 1개, 실행 중인 셸 1개당 보라 네모 1개(반지름 약 3.4px, 어두운 테두리). 같은 간격으로 돌아 겹치지 않음. 표식은 10개까지, 정확한 수는 명패·현황 판·BOARD 카드의 `서브 N`·`셸 N`.
- 수량 출처(`hansol-collector.py`): 셸 = 터미널 하단 줄의 `N shells`(Codex는 `N background terminals running`) → `shells`. 서브 에이전트 = 세션 폴더 `subagents/*.jsonl` 중 최근 90초 안에 기록된 파일 수 → `helpers`(T3 도우미 수와 큰 쪽). 긴 도구 실행 하나로 90초 넘게 기록이 없으면 빠질 수 있고, 끝난 서브 에이전트는 최대 90초 더 보임.
- 명패의 상태 줄은 칸 안에서 잘림(서브·셸 표시가 명패 밖으로 나가지 않음).

## Git 창 확장과 개발 도구 (2026-11-27)

행성 메뉴의 `GIT`이 그 작업 공간의 Git 창(커밋 그래프)을 엶. Git 창 도구 줄의 `변경`·`원격`·`도구`가 오른쪽 판을 엶(`git-work.js`).
- **변경**: 작업 파일 목록과 diff. 왼쪽 상자로 스테이지/내리기, `모두 스테이지`, `모두 내리기`. 메시지 입력 후 `커밋`. `푸시`는 확인 창(브랜치 → 원격, 커밋 수, 명령)을 거쳐 열린 Git 창이 실행하고 결과를 하단과 알림으로 표시. 원격 브랜치가 없으면 `push -u`. 브랜치 목록에서 전환(추적 중인 파일이 바뀌어 있으면 막음). 강제 푸시는 없음.
- **원격**: GitHub 저장소는 `gh`로 열린 PR과 최근 CI 실행. GitLab 저장소는 `py/hansol-gitlab.py`가 Git 자격 증명 관리자에 있는 토큰(`git credential fill`)으로 열린 MR, 이슈, 최근 파이프라인을 읽음. 토큰은 화면·파일·명령줄에 남지 않음. 항목을 누르면 웹으로 열림. GitLab은 10초 이상 걸릴 수 있음.
- **도구**: 탐색기, VS Code, 이 폴더의 새 터미널 탭, 저장소 웹, `package.json` 명령(누르면 새 탭에서 `npm run`), `.env` 점검(`.env.example`에 있고 `.env`에 없는 키 이름만), 열린 포트(LISTENING, 프로그램 이름·PID). 원격 머신 저장소에서는 Git 기능만 사용.
- 점검 명령: `hansol.git:<폴더>@changes|remote|tools`, `hansol.gitdo:<pane:x|stage-all|toggle:경로|diff:경로|commit:메시지|push|push-yes|switch:브랜치|tool:종류>`, `hansol.gitfor:<행성계 이름>`, `hansol.mosses:enter:<n>:<느리게 배수>`(워프 느린 재생).
- 추가 후보 검토: `docs/dev-tools-review.md`.

## 행성 메뉴 (2026-11-27)

행성을 오른쪽 클릭하면 행성 메뉴가 뜸. 상단 띠와 BOARD 칸 머리의 `GIT` 버튼은 삭제.
- **RADAR(OVERVIEW·행성계 화면)**: 행성 가장자리에서 선이 나와 세로 줄기로 이어지고, 줄기에서 갈라진 짧은 선이 각 버튼에 닿음(명패가 위성에 이어진 것과 같은 모양). 고른 행성에 점선 고리. 메뉴는 바닥의 맨 위 층(위성·명패·수신함·목록 위)에 불투명 판으로 그림. 오른쪽에 자리가 없으면 왼쪽으로 뜸. 빈 곳을 누르면 닫힘.
- **BOARD**: 칸 머리의 행성 그림을 오른쪽 클릭. 같은 버튼이 세로 줄기에 매달린 불투명 판으로 뜸(창 맨 위 층). 바깥을 누르거나 Esc로 닫힘.
- **항목**: 기능마다 한 줄(`mzMenuItems`). 지금은 `GIT` 하나: 누르면 커밋 그래프. 변경·원격·도구는 Git 창 안의 버튼으로 엶. 기능이 늘면 이 목록에 줄을 추가.
- Git 창 `변경` 목록은 앞 200개만 그림(748개를 한 번에 그리다 화면이 `interrupted`로 멈췄음). 모두 스테이지·내리기는 전체에 적용.
